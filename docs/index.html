Which Content Pages Actually Deserve a Refresh?

A small, honest study of staleness, visibility, and decline in a real content portfolio

Abstract. Content teams have more pages than time to review them, and "just refresh everything old" is not a plan — it's a guess. This study asks a narrower question: using only signals knowable before the fact, can staleness and visibility together point to pages actually worth a human's attention? Working with FlyRank's 30,000-page starter dataset across 32 clients, I built a transparent rule baseline, then a Logistic Regression model, and tested both under a client-grouped validation split rather than a random one. The model showed a modest, honest edge over the rule at the top of the ranking (precision@50 of 0.44 vs. 0.28), but its overall ability to tell declining pages from stable ones stayed close to chance (ROC-AUC ≈ 0.56). The result is not a strong predictor — it's a better-than-nothing sorting tool, and this paper says so plainly.

Introduction

Every content team eventually hits the same wall: too many pages, not enough hours to review them one by one. Someone has to decide what gets looked at first, and usually that decision is made informally — a gut feeling about which pages "feel" old.

That's the decision this project supports: given a portfolio of content pages, which ones should a human review first for a possible refresh? A wrong call here isn't catastrophic either way — flagging a fine page costs a few minutes; missing a genuinely declining one costs a quieter loss. That asymmetry is why this stays a decision-support tool, not an automated one.

Data

This study uses FlyRank's starter dataset: 30,000 content pages across 32 pseudonymized clients, with trailing-90-day search and engagement metrics per page (GSC and GA4 sourced).

Excluded, and why:

  • trend_direction, trend_pct — these define the label; using them as inputs means the model reads the answer first.
  • content_id, client_id — pseudonyms, used only for grouping/splitting.
  • Rows where avg_position == 0 (1,205) — means "no ranking data," not rank zero.

No client names, domains, or real search queries appear anywhere in this study.

Methodology

Baseline: A page is worth reviewing if it's gone stale (90+ days since update) and still has real visibility (300+ impressions). No fitted weights — a plain, readable rule. Both underlying signals were checked against decline rate first and came back MIXED — real pattern in the bulk of the data, weaker at the tails. Disclosed, not hidden.

Model: Logistic Regression — binary target, interpretable coefficients, the natural step up from a hand-written rule.

Label: is_declining = 1 when 30-day impressions fell >20% vs. the prior 30 days.

Validation design: Client-grouped 80/20 split, not random — a random split let the same model score 0.623 ROC-AUC by partially memorizing clients it had already seen; the grouped split scored 0.559. That six-point gap is the honest cost of the correct split.

Leakage check: Deliberately added the label-source column as a feature to test the setup — AUC jumped to a perfect 1.000, confirming leakage would be caught. The real model excludes it.

The model outperforms the rule at the top of the ranking, though both stay modest against the base rate.

The honest, client-grouped split costs 6 points of AUC compared to a random split — and that drop is the number worth trusting.

The model struggles most with genuinely fresh content (0-30 day tier: 53.8% accuracy, barely above chance). Inspected wrong cases were all recently-updated pages flagged as risky anyway — the model leans hard on low click counts, sometimes overriding a clear freshness signal.

A genuine surprise: whether keyword-context data was missing turned out to be a real signal — pages missing that context leaned toward decline, tracing back to a content-type pattern in the data.

Limitations & honest framing

Observational study, one 90-day snapshot — no claim that refreshing a page causes recovery, only that some pages look worth reviewing first. Model discrimination is weak (ROC-AUC ≈ 0.56); treat any single score as a starting point, not a verdict. Not tested on clients outside this dataset. Some flags likely reflect data artifacts (e.g. zero CTR from a tracking issue) rather than a real content problem — human review is required before any action.

Ranked recommendations

7,234 of 30,000 pages are flagged REVIEW_REFRESH, each with a reason code. An editor works the queue top-down, checking title/metadata/content before acting — the tool orders the work, it doesn't do it. Pages already strong on position and CTR that still got flagged are known weak picks; zero-click pages need a tracking check before a rewrite.

Not to automate: publishing changes from the score alone, treating the score as a guarantee, or deprioritizing a page without human confirmation.
